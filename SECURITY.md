# Security guide for auto-money-agent

## Personal Access Tokens (PAT) — read this first

A PAT is a **personal security credential tied to your GitHub account**.
It is not generated by tools, AI assistants, or anyone other than you
through GitHub's settings UI.

### Why not paste it in chat?

- Chat transcripts may persist on servers you don't control.
- Anyone with the PAT can push code, file issues, change settings on
  your behalf — until you revoke it.
- Even a revoked PAT, if leaked, is a security incident.

### Two safe locations for your PAT

| Where | Mechanism | Lifetime |
|-------|-----------|----------|
| Windows Credential Manager | `git config --global credential.helper manager` | Until you sign out / remove entry |
| macOS Keychain | `git config --global credential.helper osxkeychain` | Forever (until delete) |
| Linux cache | `git config --global credential.helper 'cache --timeout=3600'` | 1 hour |
| `~/.git-credentials` file | **❌ Don't use this** — plain text on disk | n/a |

We use the **OS-native encrypted store** by default. Your PAT never
touches a plaintext file.

### Step-by-step: generate a PAT

1. Sign in to GitHub with **wenxin202305@gmail.com** (or whatever
   email is linked to your account).
2. Open: https://github.com/settings/tokens
3. Click **"Generate new token"**.
4. Choose:
   - **Fine-grained token** (recommended, 2024+ default)
   - **Classic token** (fallback if your tooling requires it)
5. For a fine-grained token:
   - **Resource owner**: only the repo (`hainei0318/tool-station`)
   - **Repository access**: "All repositories" or just this one
   - **Permissions → Repository**: ✅ `Contents: Read and write`
   - **Permissions → Actions**: ❌ Leave (not needed for pushing)
   - **Expiration**: 30 days (you can re-create; safer than no expiry)
6. Click **"Generate token"** at the bottom.
7. **Copy the token NOW**. GitHub shows it once and only once.

### Step-by-step: use the PAT

You'll never type the PAT again after the first push, because:

1. Run `bash scripts/setup_github_auth.sh` (or double-click
   `scripts/setup_github_auth.bat` on Windows).
2. It asks for your username + repo name; configures the credential
   helper; **git push** then prompts:
   - Username: `hainei0318`
   - Password: `<paste token here; nothing appears on screen>`
3. The PAT is encrypted into Windows Credential Manager (or your
   OS equivalent).
4. Every future `git push / pull / fetch` uses the stored token.

### When to revoke

- Token is **leaked** (e.g. you pasted it somewhere you shouldn't)
- You **finished the project** and won't push for a while
- Token is **about to expire** (remake 1 day before)
- You **lost a device** that had it

Revoke at https://github.com/settings/tokens → click **Delete**.

### If you don't want a PAT at all

Two alternatives exist. Pick the one you prefer:

| Method | Pros | Cons |
|--------|------|------|
| **GitHub CLI (`gh auth login`)** | One command, walks you through browser OAuth | Slightly heavier install |
| **SSH keypair** | Most sustainable, used everywhere | 10 min setup, key on disk |

The `setup_github_auth.sh` script focuses on PAT because it's the
fastest path. For long-term use, prefer SSH keys.
